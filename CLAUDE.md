# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

Music Organiser is a Windows desktop application for managing music files, built with C# WPF (.NET 8). It provides a file browser with filtering and sorting, music metadata display, audio playback (WASAPI) with seeking, output-device selection and volume control, and file operations (copy/move/delete).

The desktop also hosts a local HTTP control API (`ControlApiService`, port 8787) driven by a companion **Flutter mobile remote app** in `remote_app/` (see "Mobile remote app" below). The mobile app can control playback, stream audio to the phone ("This device" output), and download tracks for a **pure offline mode**.

### Key Services

- **AudioPlayerService** (`Services/AudioPlayerService.cs`): NAudio-based audio playback. Pipeline `AudioFileReader → MediaFoundationResampler → VolumeSampleProvider → WasapiOut` on a selected **CoreAudio** render device. Exposes: in-app `Volume` / `LocalMuted` (both write the tail `VolumeSampleProvider._gain` — **not** `AudioFileReader.Volume`, which sits upstream of the resampler's ~1s source buffer and delays volume changes by 1–2s; for the same reason `Seek()` calls the resampler's `Reposition()` to flush its buffer so seeks are audible immediately), Windows master **`SystemVolume`** (`MMDevice.AudioEndpointVolume`), output-device selection (`OutputDeviceId`, `GetOutputDevices()`), a configurable WASAPI buffer (`OutputBufferMs`, clamped 100–1000ms, default 300, persisted in `settings.json`, transport-bar ComboBox; bigger survives render-thread starvation at 100% CPU, cost is in-app volume/audible-seek response lagging ~buffer size; changing it live re-inits the current track), and `LocalMuted` (silences local output while the phone is the audio sink — see remote-sink streaming). Live-tracks device add/remove/default-change (`IMMNotificationClient` → `DevicesChanged`) and external master-volume changes (`OnVolumeNotification` → `SystemVolumeChanged`); a removed selected device falls back to default. Critical method `StopAndReleaseFile()` must be called before move/delete operations to release file handles. On end-of-track, `OnPlaybackStopped`'s Bluetooth mid-stream-error retry is guarded by a **near-end check** (position within 2s of `TotalDuration`) so a spurious exception at a natural end doesn't replay-at-end and hang instead of auto-advancing; the ViewModel's auto-advance itself uses `Dispatcher.BeginInvoke` (not `Invoke`) so `Play()` doesn't dispose `WasapiOut` from inside its own `PlaybackStopped` callback (deadlock).

- **AudioStreamService** (`Services/AudioStreamService.cs`): Transcodes tracks to **AAC (`.m4a`)** via `MediaFoundationEncoder` for the mobile app to stream/download. Cache keyed by `path + mtime + bitrate` under `%TEMP%\MusicOrganiser\stream` (cleared on `ControlApiService.Start`), per-key lock, `Prewarm()` fire-and-forget. Bitrates snapped to `{96, 128, 160, 192}k`. Reuses `AudioFileReader` so anything that plays transcodes.

- **ControlApiService** (`Services/ControlApiService.cs`): Local `HttpListener` HTTP API on port **8787** (binds all interfaces, no auth) for the Flutter remote. Fire-and-forget per request; all state access marshalled onto the UI thread (`OnUi`). Key routes: `GET /status`, `POST /playback/{playpause,stop,next,previous,shuffle,repeat,seek}`, `POST /volume` · `/system-volume`, `GET /devices` · `POST /device` (id `"__this_device__"` = remote-sink mode), `GET /browse` (each listed subfolder includes a `tags` CSV field, batch-read in one query via `DatabaseService.GetFolderTagsBatch` rather than one call per folder) · `/files` · `/search?q=&limit=` (global library search over the SQLite cache) · `/playlist/files`, `GET /file/art?path=&i=` (a track with an embedded cover serves it for **any** `i`; otherwise candidate `i` indexes the folder's image files), `GET /file/audio?path=&bitrate=` (transcoded AAC, **Range/206**, Content-Length always set), `/playlist/*`, `/history`, file/folder rating/tags/move/delete, `POST /file/copy {path,destFolder}` (non-overwrite; a name clash keeps the existing file), `GET /files?path=&recursive=1&limit=` (recursive supported-audio listing under an arbitrary folder — `path`/`recursive` absent = unchanged legacy behavior, the currently-loaded queue; recursive defaults `limit` to 200 if unset; feeds the bulk-tag band preview player) · `GET /folder/tags?path=` · `POST /folder/tags {path,tags}` (folder tag CSV read/write) · `POST /folder/tags/suggest {path}` (band = folder name, albums = subfolder names → `MainViewModel.SuggestFolderTagsAsync`; `suggested:null` means the desktop has no `ANTHROPIC_API_KEY`), `GET /file/lyrics?path=` · `POST /file/lyrics {path,plain?,lrc?}` (save, source `manual`) · `POST /file/lyrics/find {path}` (server-side `LyricsService.FetchOnlineAsync` → AI fetch; the structured-output refusal handling means it never saves a copyright-refusal, and an instrumental track returns `success:false` with an explanatory `error`) · `POST /file/lyrics/clear {path}` (wipe a track's lyrics, mic icon off) · `GET /tags` (whole shared folder-tag vocabulary, `{name, folderCount}[]`, `folderCount` = non-deleted folders carrying it) · `POST /tags/delete {tag}` · `POST /tags/merge {from,to}` (both → `DatabaseService.DeleteFolderTag`/`MergeFolderTag`, `{success, affected}`; mirrors desktop's `Dialogs/TagManagerDialog` — see DatabaseService below). `/status`'s `nowPlaying` includes `artCount` (`1` when the track has embedded art, else the folder image count; cached per-path) plus `hasLyrics`/`synced` (per-path cached). Serves an embedded PWA on the fallback route. Started in the `MainViewModel` constructor.

- **FileOperationsService** (`Services/FileOperationsService.cs`): Handles copy/move/delete for files and folders. Automatically stops the audio player when operating on currently playing files.

- **MusicMetadataService** (`Services/MusicMetadataService.cs`): TagLib#-based metadata reader. Supported formats: MP3, FLAC, WAV, WMA, AAC, OGG, M4A. `EnumerateSupportedFiles()` returns music file paths (no tag reading) for the cache layer to diff. `GetAlbumArts(folderPath, currentFilePath?)` returns all album-art candidates in the winning priority tier (capped at 12) so the UI can cycle the cover: **the current track's own embedded pictures win outright**, else folder images / a folder track's embedded picture / subfolder images. `GetFolderImagePaths()` lists a folder's image files, preferred cover names first.

- **DatabaseService** (`Services/DatabaseService.cs`): Singleton (`DatabaseService.Instance`) SQLite cache using `Microsoft.Data.Sqlite` (raw ADO.NET, no ORM). DB at `%APPDATA%\MusicOrganiser\cache.db`, WAL mode, pooled connection per operation. Tables: `folders`, `files`, `tags`, `file_tags`, `folder_tags`, `playlists`, `playlist_entries`, `lyrics` (path-keyed `plain`/`lrc`/`source`/`synced`, LRC stored as one text blob; `GetLyrics`/`SaveLyrics`/`DeleteLyrics`). Stores file/folder attributes plus `rating` (1–5), tags, and `files.play_count` (bumped by `IncrementPlayCount`, drives least-played shuffle). All operations wrapped in try/catch so a cache failure never crashes the app. User ratings and play counts are preserved across rescans (excluded from the upsert UPDATE set). Folder-tag management (`GetFolderTagUsage()` — every tag with its non-deleted folder count, `LEFT JOIN` so a tag used only by files still lists at 0; `DeleteFolderTag(tag)`; `MergeFolderTag(from,to)`, no-op if equal/blank) powers `Dialogs/TagManagerDialog` and the mobile `/tags*` routes. Both mutators only ever touch `folder_tags` links and return the affected folder count — the shared `tags` row itself is dropped afterward **only if no `file_tags` row still references it** (`DeleteTagRowIfUnused`), since tracks and folders share one tag vocabulary.

- **FolderTreeViewModel** tag-filter/tag-manager follow-up (`ViewModels/FolderTreeViewModel.cs`): `RefreshAllFolderTagsAsync()` batch-refreshes every already-loaded `FolderNode.Tags` via `GetFolderTagsBatch` + `ApplyCache` (no write-back — the values just came from the DB) and unconditionally re-runs the active tag filter (a merge can move folders onto an already-selected tag without the selected tag *names* changing, so `SelectedTags`' change-detection alone isn't enough). Called after `TagManagerDialog` reports a change.

- **LibraryCacheService** (`Services/LibraryCacheService.cs`): Singleton orchestrating cache-first serving + in-app background refresh. `GetCachedFiles()` (instant DB read), `RefreshFolderFilesAsync()` (diff filesystem by size/mtime, re-parse only changed files, upsert, return authoritative list). Background worker (`Channel` + single consumer) services `Enqueue()` to warm neighbouring folder caches off the UI thread.

- **ArtistInfoService** (`Services/ArtistInfoService.cs`): Uses Claude Haiku 4.5 API with web search to generate artist summaries. Features:
  - Web search integration (`web_search_20250305` tool) for real-time artist lookup
  - Agentic approach: uses artist name, song title, album, and filename as context
  - Persistent caching of confident results to `%APPDATA%\MusicOrganiser\artist_info_cache.json`
  - Confidence detection via `[CONFIDENT]`/`[UNCERTAIN]` markers in responses
  - Requires `ANTHROPIC_API_KEY` in `.env` file
  - `SuggestFolderTagsAsync(bandName, albums, existingTags)` powers the folder tree's **Tag...** context-menu item: identifies the band from its folder name + subfolder (album) names via web search — the prompt specifically directs a Bandcamp search (`"<band>" bandcamp`) since Bandcamp artist/album pages carry curated genre tags, preferred over generic ones when found — and returns 3–8 lowercase genre/style tags (genre/style only — country/nationality tags like "swedish" are explicitly forbidden; era tags like "80s" are fine; a bare mood/descriptive adjective like "dark" or "atmospheric" is forbidden as its own standalone tag, but the same word inside an established genre name is fine and still allowed, e.g. "atmospheric black metal" or "dark ambient"), preferring exact spellings from `existingTags` (the DB's full tag vocabulary, via `DatabaseService.GetAllTagNames()`) so tagging stays consistent across folders. Shares the raw-REST call plumbing with the artist-summary path via a `(prompt, systemPrompt, maxTokens)` overload of `SendQueryWithWebSearchAsync`; returns `null` (no key) or an empty list (band not identified) rather than throwing. `Dialogs/FolderTagDialog` shows current tags pre-checked, appends AI suggestions as additional checked (visually distinct) checkboxes once the fetch resolves, and lets the user add custom tags before saving. **Bulk tag subfolders...** (same context menu) runs this per-subfolder over every untagged immediate child of the right-clicked folder via `Dialogs/BulkTagDialog`: batches of 20 (`BatchSize`), 3-way bounded AI concurrency (`SemaphoreSlim`) per batch, an editable-grid review (checkbox/band/tags/status) before Apply, and a Next batch button; each Apply click (not dialog close) both persists and reflects tags back onto already-loaded `FolderNode.Children` by path match, and marks its own row `IsSaved` (checkbox disables, status → "Saved", tags box shows the read-back, trimmed/deduped persisted value). Each row also has a **▶ Play** button opening a modeless `Dialogs/BandPreviewDialog`: lists every supported audio file under that band folder recursively (`MusicMetadataService.EnumerateSupportedFilesRecursive`, capped 500) and plays it via its own `AudioFileReader`/`WaveOutEvent` chain — deliberately not `AudioPlayerService`, so auditioning never touches the main app's now-playing state. Seek slider, auto-advance to the next file on natural end, single-instance (opening another band's preview closes the previous one; closing `BulkTagDialog` closes it too). **Manage tags...** (button in the folder tree's Tags filter popup, next to Clear) opens `Dialogs/TagManagerDialog`: a plain grid of every tag with its folder count, **Delete** and **Merge into** (target from a ComboBox of the other tags), both confirmed via `MessageBox` (irreversible) and hitting `DatabaseService.DeleteFolderTag`/`MergeFolderTag` directly — same "no injected services" style as the tag-filter popup itself. On close, if anything changed, `MainWindow` prunes any now-gone tag from the filter selection and calls `FolderTreeViewModel.RefreshAllFolderTagsAsync()`.

- **LyricsService** (`Services/LyricsService.cs`): Fetches + caches song lyrics. `GetCached(path)` reads the DB `lyrics` table, falling back to embedded `TagLib.Tag.Lyrics` (source `embedded`). `FetchOnlineAsync(...)` is the entry point both callers use: it walks three free, no-key sources in order and returns the **first synced (LRC) hit**, else the first plain hit, else null — and short-circuits the whole chain (including the AI call and whisper run downstream) on a `LyricsRecord.Instrumental` result, since a track with no vocals has no lyrics to find and whisper would hallucinate lines out of the instrumentation. The sources: `FetchLrcLibAsync(...)` hits [LRCLIB](https://lrclib.net) `GET /api/get` (→ `/api/search` fallback), preferring `syncedLyrics` over `plainLyrics`; `FetchLrcMuxAsync(...)` hits [LRCMux](https://lrcmux.dev) `GET /get?...&format=json`, an aggregator over Genius/KuGou/Musixmatch/NetEase/YouTube Music, building LRC from `lines[].start` (ms) only when `meta.level` is `word`/`line` (word timing flattened to one stamp per line); `FetchSyncLrcAsync(...)` hits [SyncLRC](https://synclrc.dev) `GET /lyrics`, whose `synced` is already an LRC blob (its word-level `karaoke` field is ignored) and whose plain text is flattened from that LRC when the API ships none. All three share `ApiHttp`, which sets the self-identifying `User-Agent` LRCLIB asks for. `FetchAiPlainAsync(...)` clones `ArtistInfoService`'s raw-REST web-search shape (`claude-haiku-4-5`, `web_search_20250305`) but uses **structured output**: alongside the server `web_search` tool it declares a client `provide_lyrics` tool (`{found:bool, lyrics:string}`) and a neutral "locate publicly-published lyrics" system prompt, then reads the `tool_use` block's `lyrics`/`found` (never the assistant prose) — returns `(text, confident, available)` with `available=false` when the model can't/won't provide them. Falls back to a `RefusalMarkers` heuristic if the model answers in plain text instead of calling the tool. `available=false` → the ViewModel drops into an empty manual-paste box (no refusal ever saved/synced). `Save(path,plain,lrc,source)` and `Delete(path)` (→ `DatabaseService.DeleteLyrics`) wrap the DB. Static `ParseLrc`/`BuildLrc` convert between `[mm:ss.xx] text` LRC and `List<LyricLine>` (shared with `WhisperAlignService`); a DEBUG static-ctor self-check verifies a parse round-trip. **LRC has no hours field** — minutes just keep counting (`[83:15.00]`), so both sides accumulate rather than roll over: `BuildLrc` and `LyricLine.TimeFormatted` go through `LyricLine.FormatLrcTime` (`(int)TotalMinutes`, never TimeSpan's `mm`, which wraps 1:23:15 to `23:15` and lands every post-hour line an hour early), and `LrcTagPattern` takes 1–3 minute digits. Album-length single tracks (doom/drone, e.g. Bell Witch) are the real case, not a hypothetical.

- **WhisperAlignService** (`Services/WhisperAlignService.cs`): Fallback synced-lyrics generator when only plain lyrics exist. Uses **Whisper.net** (whisper.cpp, pure .NET — no Python); auto-downloads `ggml-base.bin` once to `%APPDATA%\MusicOrganiser\models\` (via `WhisperGgmlDownloader`, `.partial` + atomic rename). `AlignAsync(audioPath, plainLyrics, progress, ct)` decodes the track to 16kHz mono via NAudio, transcribes with **token timestamps** (`WithTokenTimestamps()`; `WhisperToken.Start/End` are raw centiseconds → `×10` ms, unlike `SegmentData` which is pre-converted), forward-scan aligns each lyric line to the first matching transcript word, interpolates gaps, and spreads a trailing run of unmatched lines (whisper lost the vocals) evenly toward the song end (`totalDuration` from the sample count) rather than piling them on the last match, clamps monotonic, and emits LRC. Slow; runs off the UI thread with progress. `// ponytail:` naive forward-scan align + base model, no vocal isolation, heuristic tail-spread (hand-tune with the ⏺ buttons) — upgrade path (medium model / Demucs / whisperX) noted in-code.

### Key ViewModels

- **MainViewModel** (`ViewModels/MainViewModel.cs`): Central state management for the application, owns all services and coordinates between folder tree, music grid, and audio player. Exposes `Volume`, `SystemVolume`, `OutputDevices`/`SelectedOutputDevice` (record `Models/OutputDeviceItem`), and `RemoteSink` (phone is the audio sink). Subscribes to `AudioPlayerService` events and marshals device/volume changes to the UI thread.

- **FolderTreeViewModel** (`ViewModels/FolderTreeViewModel.cs`): Manages folder tree with lazy-loading expansion, filtering, and sorting via `FolderNode` class. `LoadChildrenAsync` batches cache-node adds into a single UI dispatch (cache pass + disk-diff pass) for near-instant rendering; `NavigateToPathAsync` expands the ancestor chain and selects the target.

### Important Patterns

1. **File Handle Management**: Before any move/delete operation, always call `AudioPlayerService.StopAndReleaseFile()` to prevent file-in-use errors. The `FileOperationsService` handles this automatically. Deleting or moving a *track* goes through **`MainViewModel.DeleteFileAsync(path)` / `MoveFileAsync(path, destFolder)`** (both thin wrappers over the private `LeaveQueueAsync`), not `FileOperations` directly — every entry point (grid context menu, now-playing Delete/Move buttons, drag & drop, the Move-to-artist-folders helpers, mobile `POST /file/delete` · `/file/move`) routes through them, so removing the playing track from the queue **continues with the queue's next track** instead of stopping the music (`StopAndReleaseFile` detaches `PlaybackStopped` before stopping, so the normal auto-advance never fires for a moved or deleted file). It picks the successor *before* the delete (same wrap rule as `Next()`: wrap only under Repeat-All), then removes the row from `MusicFiles` in place — never a `LoadFolder` reload, which would rebuild the queue (and wipe a playlist / recursive-tree queue) under the track about to play — prunes it from the shuffle history, and enqueues a `LibraryCacheService` refresh for the source folder (and, for a move, the destination) so the DB reconciles both ends.

2. **Last session restore**: `settings.json` keeps `LastFolderPath` (folder browsed) **and `LastPlayedPath`** (track playing at close, written in `PlayFile`). `RestoreLastFolderAsync` re-opens the folder and arms `MainViewModel._restoreSelectPath` so the track is re-selected — not played — once the grid holds it, so the transport's Play resumes it (`PlayPause` falls back to `SelectedFile`). The request has to survive the async fill: it is applied after **both** grid passes (cache, then authoritative refresh), the cache pass skips its usual "select the first file" while one is pending, and the tree-selection echo re-runs `LoadFolder` for the same path. It retires when you browse to another folder or play anything. `SelectionRestored` tells `MainWindow` to centre the row (`CentreGridOn`, see #19 — a Selector selects without scrolling). Only armed when the track still exists **and** lives in the restored folder.

3. **Recent Folders**: Stored in `%APPDATA%\MusicOrganiser\recent_folders.json`. Separate lists for Copy and Move operations (10 items each).

4. **Artist Info Cache**: Stored in `%APPDATA%\MusicOrganiser\artist_info_cache.json`. Caches AI-generated artist summaries when confidence is high. Can be refreshed via the refresh button in the UI.

5. **Async Loading**: Folder tree and music file list use async loading to keep UI responsive. Folders load children on expansion, music files load when a folder is selected.

6. **Folder Filtering**: Filter text propagates down the tree via `FilterText` property, exactly mirrored by a tag filter on `MatchSet` (`TagMatchSet?`, set from `FolderTreeViewModel.SelectedTags`). Unlike the name filter, the tag filter can't be resolved by walking loaded nodes — a tagged folder is typically several levels below anything currently expanded, and unloaded subtrees are dummy nodes that can never match — so it's **DB-driven**: `SelectedTags`'s setter calls `DatabaseService.SearchFolderPathsByTags` (**ANY** of the selected tags, not all) off the UI thread, builds a `TagMatchSet` (`Matches` = normalized hit paths, `Ancestors` = every ancestor prefix of every hit, so matches stay reachable from a visible root), and propagates it down the tree exactly like `FilterText`/`SortOption`. Visibility (`IsVisible`) while a match set is active is `(name matches AND (own path in Matches or Ancestors)) OR any child is visible`; dummy (unloaded) nodes are never visible while a tag filter is active. After building the match set, `FolderTreeViewModel` **materializes** up to 200 of the DB hits — `EnsurePathMaterializedAsync` (also used by `NavigateToPathCoreAsync`) expands + loads each ancestor level so the matching `FolderNode`s actually exist in the tree — without selecting anything or triggering **Band-folder auto-descend** (#17). Clearing the filter (`MatchSet = null`) restores prior behavior without collapsing anything. UI: the filter/sort panel's **Tags** `ToggleButton` + `Popup` (`MainWindow.xaml`) — a checkbox list read fresh from `DatabaseService.GetAllTagNames()` on every open (picks up newly-saved tags), selections tracked in `MainWindow`'s `_selectedFolderTagFilters` and pushed to `FolderTree.SelectedTags`; button label becomes "Tags (n)" when active. The mobile app's folder-tag filter (`library_screen.dart`, client-side over the current listing) uses the same ANY-of-selected-tags rule. A **^** button next to the filter box (`UpLevel_Click`) selects the current selection's parent and folds it (`IsExpanded = false`) — safe against Band-folder auto-descend because the parent is already expanded at that point, so `UnfoldedBySelection` computes false and `JumpIntoFirstAlbumAsync` no-ops.

7. **Folder Sorting**: Sort option propagates down the tree via `SortOption` property. Supports Name (A-Z/Z-A), Creation Date, and Modified Date in both ascending and descending order.

8. **Right-Click Context Menus**: Use `MouseRightButtonDown` (bubbling event) with `e.Handled = true` to correctly identify the clicked item. Do not overwrite the clicked item reference in menu opened handlers. The folder tree's menu also has **New subfolder** (`FolderNewSubfolder_Click`): `TextInputDialog` for the name, `Directory.CreateDirectory`, then `IsExpanded = true` **before** `Refresh()` (Refresh only reloads children of an open node).

9. **Cache-First Loading**: Folder tree and music grid read from the SQLite cache first (instant), then run a background refresh (`LibraryCacheService.RefreshFolderFilesAsync` / `FolderNode.LoadChildrenAsync`) that diffs the filesystem, upserts the DB, and reconciles the UI (add/remove/replace). Initialized in `MainViewModel` constructor; worker stopped in `Dispose`. **Instance identity matters**: `RefreshFolderFilesAsync` always hands back freshly-constructed `MusicFile` objects (even for unchanged files, since it re-reads the DB), but `MainViewModel.NowPlaying`, `GetAdjacent`'s shuffle history, and the grid's `SelectedFile` all hold references into `MusicFiles`. `ReconcileMusicFiles` therefore keeps the existing grid instance for a path unless the file actually changed on disk (`FileSize`/`FileModifiedUtc` beyond a 2s tolerance), reassigning `NowPlaying` only when the currently-playing instance itself was replaced — otherwise a harmless background refresh mid-playback silently orphaned those references and killed auto-advance/Next/Previous. `GetAdjacent` also falls back to a path match if `MusicFiles.IndexOf(current)` misses, as a second line of defense.

10. **Ratings & Tags**: 1–5 star rating and comma-separated tags for tracks (`MusicFile`, `INotifyPropertyChanged`) and folders (`FolderNode`). UI via the reusable `Controls/StarRating` control + an inline tags box; both reveal on row hover (`StarRating.EditMode` / visibility triggers bound to row `IsMouseOver`). **The grid's `CellStyle` must set `Foreground`/`BorderBrush` itself.** An explicit `DataGridCell` style replaces the theme style's *setters*, but the theme's *triggers* still drive every property the explicit style leaves alone (explicit-style setters outrank theme-style triggers). The theme's `IsSelected` trigger paints Foreground white and BorderBrush highlight-blue on the assumption its own Background trigger painted the cell blue — which the style's `Background="Transparent"` setter (needed so the album art shows through) suppresses. The selected row therefore rendered as white text on a white row inside blue cell outlines, with a black outline on the focused cell (`IsKeyboardFocusWithin`): it read as a strip of blank boxes, not as a selection. Fixed by explicit `Foreground`/`BorderBrush` setters plus the three row states, all painted on the **cells** (the row's own Background sits behind them) with **trigger order as priority — later wins**: hover `#EBF4FE` (DataTrigger on the parent `DataGridRow.IsMouseOver`) → selected `#CCE8FF` (focus-independent, so it never dims) → now-playing `#90CAF9` + SemiBold + the row's left accent bar, which outranks both so the playing marker never flickers under the mouse. The grid also pins **`RowHeight="22"`**: the hover-revealed editors are taller than what they replace (an unrated `StarRating` collapses all five stars to zero height until hover; the tags TextBox outgrows its TextBlock), so without a pinned height every hover re-measured the row and the list nudged itself a few pixels under the cursor. Keep new cell content within 22px. Edits write through to `DatabaseService` (`SetFileRating`/`SetFileTags`, `SetFolderRating`/`SetFolderTags`). Folder edits self-create the DB row via `EnsureFolderRow`; `FolderNode` guards write-back during cache load with `ApplyCache`/`EnablePersist`. The **player panel's now-playing row** (filename row of the transport bar) carries the same always-editable `StarRating` + tags box bound at `NowPlaying.Rating`/`NowPlaying.Tags` — no extra persistence code, since `NowPlaying` is the very `MusicFile` instance in `MusicFiles` that `File_PropertyChanged` already writes through — plus **Copy/Move/Delete** buttons acting on the *playing* file instead of the grid selection (`NowPlaying{Copy,Move,Delete}_Click`). Copy/Move pop the same recent-folders + `Browse...` list as the grid's context menu and reuse its duplicate-conflict handling via `CopyFiles`/`MoveFiles` (the list-taking form of `CopySelectedFiles`/`MoveSelectedFiles`).

11. **Output device & system volume**: The transport bar has a device `ComboBox` (bound to `OutputDevices`/`SelectedOutputDevice`), an in-app volume bar, and a Windows-master (`SystemVolume`) bar. The master bar reflects external volume changes live (CoreAudio `OnVolumeNotification`); the device list updates live on Bluetooth/USB connect/disconnect (`IMMNotificationClient`). The selected device id is persisted in `settings.json` (`OutputDeviceId`); the master volume is a live OS value and is not persisted.

12. **Remote-sink streaming**: When the mobile app selects "This device", `POST /device {id:"__this_device__"}` sets `MainViewModel.RemoteSink` → `AudioPlayerService.LocalMuted = true` (desktop plays silently but keeps the queue/position clock and auto-advance). The phone streams the current track's transcoded AAC (`/file/audio`, prewarmed for the current + next track) and follows `/status`. `/status.outputDeviceId` reports `"__this_device__"` while active.

13. **Least-played shuffle**: Shuffle has no fixed permutation. `MainViewModel.PickLeastPlayed` picks at random among the queue's tracks with the lowest persisted `MusicFile.PlayCount`, skipping anything in `_shufflePlayed` (paths played this cycle) so one pass still covers the whole queue; the cycle clears on wrap (repeat All) and returns null at the end when repeat is off. `RecordPlay` (in `PlayFile`) bumps the count in memory + DB and appends to `_shuffleHistory`, which Previous retraces (and Next steps forward through after a Previous). Any queue change or shuffle toggle calls `ResetShuffleState()`. The phone remote inherits this via the API; the offline player's own shuffle is still a plain permutation.

14. **Player buttons**: Transport buttons use a flat circular `PlayerButtonStyle` (`MainWindow.xaml` resources); play/pause is a larger accent-filled `PlayerPlayButtonStyle`. Shuffle/repeat grey when off, black-on-blue-circle when on (via `DataTrigger` on `Background`; the template `TemplateBinding`s `Background` so the triggers apply).

15. **Album cover**: The cover follows the *playing track*, not the folder — `PlayFile` calls `MainViewModel.LoadAlbumCoverAsync(folder, filePath)`, which owns its own `CancellationTokenSource` so fast track switches cancel stale loads. Multi-candidate folders cycle every 15s and crossfade via `AlbumCoverGhost` (`AlbumCoverImage_TargetUpdated` in `MainWindow.xaml.cs`). `UpdateAlbumCoverPosition` shifts the cover below the file rows using a **`TranslateTransform`** — never a `Margin`: margin participates in layout, shrinking the `Stretch="Uniform"` image's available height, which grows the offset, which shrinks it further (a self-collapsing feedback loop).

16. **Lyrics & karaoke sync editor**: A collapsible lyrics panel is the 4th right-panel row, between `CoverHost` and the player bar (toggled by `ShowLyrics` / the 🎤 transport button, which is a *smart* toggle — `StartKaraokeCommand`: synced → straight to karaoke big-view; else runs the Find flow and enters karaoke only if it ends synced). Lyrics load on play from cache/embedded tags only (`LoadLyricsFromCacheAsync`, no network). Header buttons: **Find** (on-request `FetchOnlineAsync`, i.e. LRCLIB → LRCMux → SyncLRC, → structured-output AI → on refusal/miss, an empty manual-paste box; an instrumental hit stops with a status message and saves nothing), **Sync** (`WhisperAlignService` → LRC), **Karaoke** (big-view toggle, mutually exclusive with Edit via the two setters), **Edit** (toggles inline row editing; on a synced track it edits words+timing in place, NOT the raw plain-text box — that's only for unsynced lyrics — so Edit never zeroes timestamps), **Clear** (`DeleteLyrics` + empty paste box), **Follow** (re-arms auto-scroll).
    - **No manual Save** — edits auto-save (debounced ~500ms, `PersistTimedLines`/`PersistRawText`).
    - **Time-proportional row layout**: each row carries a `GapPx` spacer above it = `(thisLine.Time − prevLine.Time) × LyricRowPxPerSecond` (first row = intro length; row-height subtracted so line-to-line *positions* are proportional, floored at `MinGapPx`). `RecomputeLyricRowGaps` runs on load and on any `Time` edit. `LyricsListBox` uses `CanContentScroll=False` (pixel scrolling).
    - **Playhead + auto-follow** (`MainWindow.xaml.cs`): a `LyricsPlayheadLine` sits at `currentSeconds × LyricRowPxPerSecond − VerticalOffset`; `AutoScrollLyrics` keeps "now" centered, driven by `CurrentPosition`. Auto-scroll **freezes** while a row is selected (indefinitely — you wait for the vocal, then tap ⏺), while the mouse is over the list, or for 5s after a manual scroll; Esc or the Follow button releases it.
    - **Hand-timing**: per-row −/⏺/+ buttons. ⏺ (`SetLyricLineNow`) stamps `CurrentPosition − OutputBufferMs` (latency-compensated to what you *hear*); ±0.2s nudges. All route through `RetimeLine`, which **ripple-shifts** every later line by the same delta.
    - **Active-line highlight**: `OnPositionChanged` binary-searches `LyricsLines` → `IsActive`/`CurrentLyricIndex`; DataTriggers give the active line bold blue text + a `#DCEBFB`/`#90CAF9` highlight band (both view and edit mode). Karaoke big-view (`KaraokeWindow`) is a stable all-lines `ItemsControl` panned via a `TranslateTransform` (`PanKaraokeToCurrentLine`, 350ms ease) with a top/bottom `OpacityMask`.
    - **Position updates are coalesced**: `OnPositionChanged` records the latest position and queues at most one `Dispatcher.BeginInvoke` (guarded by `_positionUpdatePending`) — the timer fires on overlapping ThreadPool threads, so a synchronous `Invoke` there piled up and froze the UI.

17. **Band-folder auto-descend**: `FolderTreeView_SelectedItemChanged` → `JumpIntoFirstAlbumAsync`: selecting a folder that holds *only* album subfolders (no music files of its own, and no subfolder has subfolders) immediately selects its first child — **only when that selection is what unfolded it** (`FolderNode.UnfoldedBySelection`, set in the `IsSelected` setter before it expands); re-selecting an already-open folder does nothing. Guarded by a re-check of `folder.IsSelected` after the load/refresh awaits so a fast second click isn't overridden; no recursion risk since the album folder has no children.


18. **Drag & drop**: Grid files (multi-select) and folder-tree nodes drag onto any folder-tree node — **move by default, Ctrl = copy** (Explorer convention, `EffectFor`). Plain WPF `DragDrop.DoDragDrop` with two private clipboard formats (`MusicOrganiser.Files` carrying the `List<MusicFile>`, `MusicOrganiser.Folder` carrying the `FolderNode`); the drag starts from `MouseMove` past `SystemParameters.Minimum*DragDistance` after `DragSource_PreviewMouseLeftButtonDown` recorded the origin. Sources are filtered so normal interaction survives: the grid drags only from a `DataGridRow` (scrollbar/headers/empty space unaffected), the tree ignores expander (`ToggleButton`) presses and refuses drive roots (`Parent == null`). `DropTarget()` is the single validity gate used by both `FolderItem_DragOver` (sets `Effects`, `None` = no-drop cursor) and `FolderItem_Drop`: no unknown payloads, no dropping files into the folder they already live in, and for folders no self-drop, no drop into the current parent, and no drop into their own subtree (`IsUnder`). Both handlers set `e.Handled` so the innermost node wins instead of the drop also bubbling to ancestors. The drop itself just calls the existing `CopyFiles`/`MoveFiles`/`CopyFolderWithDuplicateCheck`/`MoveFolderAsync` helpers (so duplicate dialogs, handle release and grid reload all behave as from the context menus), then `MarkAsDeleted()`s the moved source node and `IsExpanded = true` + `Refresh()`es the target. Folder *moves* confirm via `MessageBox` first (a mis-drop relocates a whole tree); file drops don't. Not wired: drops from Explorer (`DataFormats.FileDrop`), drag adorners/insertion lines, hover-to-auto-expand.

19. **The grid follows the playing track**: `PlayFile` sets `SelectedFile = file` alongside `NowPlaying`, so *every* entry point (grid double-click, Next/Previous, end-of-track auto-advance, least-played shuffle, the phone remote, the post-delete/move successor) leaves the playing row selected — one place, not per-caller. `MainWindow.ViewModel_PropertyChanged` reacts to `NowPlaying` by calling **`CentreGridOn`**, which `ScrollIntoView`s the row (realizes it under virtualization) and then puts it in the **middle** of the viewport via the DataGrid's `ScrollViewer` — `VerticalOffset = index − (ViewportHeight − 1) / 2`. Offsets are counted in **rows, not pixels** (the DataGrid's default item-based scrolling with `RowHeight="22"`); a `// ponytail:` comment names that assumption. Deferred to `DispatcherPriority.Background` because the row may have only just been added by the folder load. Shuffle is the case that motivates it: it jumps anywhere in a long folder, and without centring you'd have to hunt for what's playing.

## Mobile remote app (`remote_app/`)

A Flutter app (package `music_organiser_remote`) that controls the desktop over the LAN HTTP API. Ships to iOS TestFlight via `.github/workflows/ios-testflight.yml` (tag `v*`). Plain state via `ChangeNotifier` + `ListenableBuilder` — no Provider/Bloc.

- **`lib/app_state.dart`** — `AppState`: connection lifecycle, 1s `/status` poll, `ApiClient`, and the local `just_audio` player used for "This device" streaming (`_syncLocal` slaves the phone to `/status`: load on track change, mirror play/pause, resync on drift, retry failed loads). Owns the offline sub-services.
- **`lib/api_client.dart`** — thin `http` wrapper over the desktop API; `copyFile(path,dest)` / `moveFile(path,dest)` / `deleteFile(path)`; `streamUrl(path,bitrate)` / `artUrl(path,[i])` (art candidate index, omitted from the URL when `0`); `lyrics(path)` (GET), `setLyrics(path,{plain,lrc})` / `findLyrics(path)` / `clearLyrics(path)` (POST); `folderTags(path)` (GET) / `setFolderTags(path,tags)` (POST) / `suggestFolderTags(path)` (POST, returns `FolderTagSuggestion`); `tags()` (GET `/tags`, the whole shared folder-tag vocabulary) / `deleteTag(tag)` / `mergeTag(from,to)` (POST `/tags/delete` · `/tags/merge`). `LyricsData`/`LyricLine` (with an LRC-parsing `lines` getter), `FolderTagSuggestion` (`suggested` null = AI unavailable), and `TagUsage` (`{name, folderCount}`) live in `lib/models.dart`; `NowPlaying` carries `hasLyrics`/`synced`.
- **Screens** (`lib/screens/`): Now Playing, Library (browse + search + 6-option sort mirroring the desktop, `lib/sort_utils.dart`, plus a tag filter — a tag icon next to sort opens a bottom sheet of `TagChip`s built from the tags present in the current listing (`FolderEntry.tagList`, from `/browse`'s new `tags` field); tapping toggles inclusion, folders are filtered client-side requiring ANY selected tag (case-insensitive), same rule as the desktop tree filter; hidden in search mode since search returns tracks not folders; the sheet's header also has a **Manage tags** button opening `_ManageTagsPage` — a thin client over `GET /tags` listing the whole shared vocabulary with delete / merge-into actions (confirm dialogs, mirroring desktop's `TagManagerDialog`), refreshing the current listing on return), Playlists, History, and **Downloads** (offline). Connect screen has a "Browse offline" entry. Library's folder ⋮ menu has a **Tag folder** sheet (`_FolderTagSheet`): current tags as deletable chips, an AI suggestion pass that runs automatically on open (ghost chips, tap to add), a custom-tag field, and Save. **Bulk tag** (same menu) opens a full-screen `_BulkTagPage`: thin client mirroring the desktop's bulk-tag flow over the same `/folder/tags*` endpoints — `/browse` lists subfolders, a `folderTags` GET per subfolder finds untagged ones (the `/browse` response doesn't carry tags), `suggestFolderTags` runs with 3 concurrent futures per batch of 20, rows are editable before Apply, and Next batch continues; Apply updates each saved row in place (re-reads `folderTags` for the persisted value, disables its checkbox). Each row's ▶ icon opens a preview bottom sheet — a sheet-local `just_audio` player (not `AppState`'s) streams files from the new `filesRecursive` (`GET /files?recursive=1`) listing, with seek + auto-next. Now Playing's big art cycles through `NowPlaying.artCount` candidates (one every 15s, `_CyclingArt` in `now_playing_view.dart`) when the folder has more than one image and the track has no embedded cover (`artCount` is 1 if it does), crossfading via `AnimatedSwitcher` after precaching the next candidate; small tiles elsewhere stay static. A 🎤 header toggle swaps the big art for a karaoke lyrics panel (`_KaraokeView`): active line (last whose timestamp ≤ `status.positionSec`, 1s granularity) is highlighted + auto-scrolled; plain-only lyrics show un-highlighted; Find/Edit (plain text)/Clear live in the panel — lyrics are fetched on track change (`AppState._loadLyricsForTrack`, only when `hasLyrics`) and cached. The desktop-only sync editor (time-proportional layout, whisper, hand-timing, playhead/auto-scroll) is not mirrored — the phone displays synced lyrics and does basic find/edit/clear only. Every track list's ⋮ sheet (`showTrackActions`, `lib/screens/track_actions.dart`) has a **Copy to…** tile next to **Move to…**, both sharing one folder picker (`_MovePicker`) parameterized by a `verb`.
- **Streaming**: the output picker lists desktop devices plus **"This device"** — selecting it streams transcoded AAC to the phone (Low/Med/High = 96/160/192k, `streamBitrate` pref) and mutes the desktop.
- **Offline mode** (`lib/offline/`): `OfflineStore` (JSON manifest at `<app-docs>/downloads/manifest.json`, mirrored desktop folder tree, path sanitization), `DownloadService` (serial download queue → `.part` → rename, progress/cancel/retry), `OfflinePlayer` (own `AudioPlayer`, local transport: next/prev/shuffle/repeat/auto-advance; mutually exclusive with remote-sink streaming). Download a track/folder/playlist from the ⋮ menus; browse + play with no desktop connection.

Build/run: `cd remote_app && flutter run` (connect to `<desktop-LAN-ip>:8787`; use `10.0.2.2:8787` from an Android emulator).

## Dependencies

### Desktop
- **NAudio** (2.2.1): Audio playback and volume control
- **TagLibSharp** (2.3.0): Audio metadata reading
- **Microsoft.Data.Sqlite** (8.0.10): Local SQLite cache for files and folders
- **Anthropic.SDK** (5.9.0): Claude AI API client for artist summaries
- **Whisper.net** + **Whisper.net.Runtime** (1.9.1): On-device speech recognition (whisper.cpp) for aligning plain lyrics to audio (karaoke sync fallback)

- NAudio 2.2.1 (meta-package) also provides CoreAudio (`WasapiOut`, `MMDeviceEnumerator`, `AudioEndpointVolume`) and MediaFoundation (`MediaFoundationEncoder`/`Resampler`) — no extra packages needed for device selection, system volume, or AAC transcoding.

### Mobile (`remote_app/pubspec.yaml`)
- **http**, **shared_preferences**, **just_audio** (local playback / streaming), **path_provider** (offline downloads dir)
